================================================================================
                         KEY CONCEPTS AT A GLANCE
================================================================================

THE CORE RULE:
──────────────
E2E Testing = Real Browser + Real Backend, ZERO Mocks

If you use page.route() to mock API calls, you're not writing E2E tests.

THREE TIERS:
────────────
1. SETUP        → Authenticates once, saves storage state
2. AUTHENTICATED → Reuses auth for parallel test execution
3. PUBLIC       → No auth needed, tests unauthenticated flows

SPEED COMPARISON:
──────────────────
Per-test login:  320+ seconds (20s × 16 tests)
Storage state:   8-10 seconds (setup once + parallel)
Speedup:         30-40x faster

PAGE OBJECTS:
─────────────
• Locators defined in one place (pages/ directory)
• Tests reference page objects
• UI change? Update 1 file, all tests still work

SEVEN ANTI-PATTERNS:
────────────────────
1. page.route() mocks (P1 critical)
2. Per-test login (P2 performance)
3. Hardcoded locators (P2 maintainability)
4. Multiple journeys (P3 debugging)
5. Skipped tests (P1 technical debt)
6. Arbitrary timeouts (P2 flakiness)
7. Testing details (P3 brittleness)

================================================================================
                         PREVENTION CHECKLIST
================================================================================

BEFORE WRITING TESTS:
☐ Is this really E2E? (complete journey, real API)
☐ Identify auth tier (public, authenticated, admin)
☐ Test data exists (test user accounts)
☐ Backend accessible (E2E needs real API)

WHILE WRITING:
☐ Create page object (pages/ directory)
☐ One test file per page/feature
☐ Single journey per test (not 5 in 1)
☐ Real API calls only (no page.route)
☐ Explicit waits (waitForURL, waitForResponse, toBeVisible)
☐ Test data via environment variables
☐ Page objects reusable

BEFORE COMMITTING:
☐ All tests pass
☐ No console errors
☐ No skipped tests (.skip forbidden)
☐ No mocks anywhere
☐ Tests run < 30 seconds
☐ Page objects used for all locators
☐ Auth setup runs first
